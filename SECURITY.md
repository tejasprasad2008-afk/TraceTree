# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 0.1.x   | :white_check_mark: |
| < 0.1   | :x:                |

## Reporting a Vulnerability

We take the security of TraceTree seriously. If you believe you have discovered a vulnerability, security flaw, or supply-chain risk within TraceTree, please disclose it responsibly.

### Disclosure Contact
Report security issues privately via email to:
**tejasprasad2008@gmail.com**

Please include the following details in your report:
- **Type of issue**: (e.g. command injection, sandbox escape, insecure deserialization, denial of service)
- **Affected component**: Source file paths and commit / version tag
- **Reproduction**: Step-by-step instructions or minimal proof-of-concept payload
- **Impact**: Assessment of confidentiality, integrity, or availability consequences

### Response & Handling Timeline
- **Initial Response**: Within 48 hours of receipt.
- **Triage & Assessment**: Within 5 business days, confirming vulnerability scope and remediation plan.
- **Remediation & Advisory**: A coordinated patch and GitHub Security Advisory (GHSA) will be published upon fix verification. Credit will be acknowledged in release notes.

Please do not open public GitHub issues or discuss potential vulnerabilities in public forums until a fix has been published.
